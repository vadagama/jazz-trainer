# I18N — Поддержка нескольких языков на лендинге и в приложениях

**Дата:** 2026-07-26
**Статус:** 🟡 Черновик
**Горизонт:** 1–2 версии (2–4 недели)

## 1. Резюме (Executive Summary)

Amazilia — веб-сервис, который при запуске был полностью на русском языке. Аудитория расширяется — лендинг уже получил примитивную EN/RU-локализацию, а само приложение (React + 16 плагинов) остаётся полностью русскоязычным.

Добавляем **сквозную поддержку локализации** на всех уровнях: лендинг (Vanilla JS), веб-приложение (React), плагины (контент, UI), API (email-шаблоны, ошибки). Выбираем легковесный подход на базе `react-i18next` для React-дерева и стандартного `i18next` для Vanilla-лендинга. Все словари хранятся в JSON-файлах **рядом с кодом** (co-location, принцип 5 из ARCHITECTURE_VISION.md).

Ключевая ценность: **международная аудитория получает сервис на своём языке** — от лендинга и плейера до упражнений и email-рассылок. Для разработчиков — единый механизм локализации с автодополнением ключей через TypeScript-типы, без магических строк.

## 2. Текущее состояние

| Слой                           | Статус i18n                                                                                                          | Языки                 |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------- | --------------------- |
| **Лендинг** (`apps/landing/`)  | 🟡 Примитивная EN/RU локализация. Словарь в одном JS-файле (`I18N` объект), HTML-элементы с `data-i18n` атрибутами. | `en`, `ru`            |
| **Веб-приложение** (`apps/web`) | 🔴 Нет i18n. Все строки захардкожены на русском. `toLocaleString('ru-RU')` в админке.                               | Только `ru`           |
| **Плагины** (16 шт.)           | 🔴 Нет i18n. Все строки в `*.tsx`-файлах на русском или смеси en/ru.                                                | Только `ru`           |
| **API** (`apps/api/`)          | 🔴 Нет i18n. Email-шаблоны (`magicLink`, `welcome`) захардкожены на английском.                                     | Только `en`           |
| **Ядро** (`music-core`)        | ⚪ Не требует i18n. Чистая логика без UI-строк.                                                                     | —                     |

### 2.1. Проблемы текущего подхода на лендинге

- **Словарь в одном файле `main.js`** — 180 строк JSON-подобного объекта. С ростом числа ключей файл станет неподдерживаемым.
- **Нет структуры.** Все ключи в плоском неймспейсе (`hero.h1`, `features.f1d`). Добавление нового языка = копирование всей структуры руками.
- **Нет TypeScript-типизации.** Опечатка в `el.dataset.i18n` = пустая строка на экране, молча.
- **Нет плюрализации.** `forwhom.s4d` — фиксированный текст. Для языков с plural forms нужна логика.
- **Нет интерполяции.** Нельзя вставить BPM или имя стиля внутрь строки.

### 2.2. Проблемы отсутствия i18n в приложении

- **Закрытая аудитория.** Сервис доступен только русскоязычным музыкантам. Англоязычная аудитория джазового EdTech (основной рынок) исключена.
- **Даты/числа захардкожены.** `toLocaleString('ru-RU')` в админке, `localeCompare(b.name, 'ru')` — сломано для других языков.
- **Контент плагинов не локализован.** Упражнения, квизы, теория — всё на русском.

## 3. Форматы локализации и что нужно переводить

### 3.1. Что подлежит локализации

| Категория                          | Примеры                                                                             | Где                                                        |
| ---------------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| **UI-строки**                      | Заголовки, кнопки, лейблы, плейсхолдеры, навигация                                  | `apps/web`, `apps/landing`, все плагины                    |
| **Маркетинговый контент**          | Hero, features, how-it-works, сравнение с конкурентами                              | `apps/landing`                                             |
| **Учебный контент**                | Названия упражнений, описания концепций, подсказки                                  | Плагины `theory.*`, `practice.*`, `assess.*`               |
| **Email-шаблоны**                  | Magic Link, Welcome, уведомления, счета                                              | `apps/api`                                                 |
| **API-ответы (ошибки)**            | Сообщения об ошибках валидации, 404, 403                                            | `apps/api` (если отображаются пользователю)                |
| **Даты, числа, валюты**            | Форматы дат, цены подписок, продолжительность                                        | `apps/web`, все плагины                                    |
| **Аккордовая нотация**             | `Cmaj7` vs `До_маж7` (нужна ли? — `[assumption]` нет, аккорды интернациональны)     | `music-core`, `apps/web` (только если нужна кириллическая) |
| **SEO-метаданные**                 | `<title>`, `<meta description>`, `og:`-теги                                         | `apps/landing` (уже частично), `apps/web`                  |
| **Accessibility (aria-лейблы)**    | `aria-label`, `title`-атрибуты                                                      | `apps/web`, все плагины                                    |

### 3.2. Что НЕ переводим

- **Аккордовые символы:** `Cmaj7`, `Dm7b5`, `G7alt` — интернациональный стандарт. Кириллическая нотация (`До_маж7`) не нужна.
- **DSL-синтаксис:** `| Cmaj7 | Dm7 G7 |` — язык гармонических сеток, не зависит от языка пользователя.
- **Ноты и MIDI-данные:** `C4`, `Eb5` — интернациональный стандарт.
- **Названия стилей:** `Swing`, `Bossa Nova` — международные термины. [assumption: не переводим, но можно добавить tooltip-перевод]

## 4. Целевая архитектура

### 4.1. Выбор библиотеки

| Кандидат             | Плюсы                                                                                          | Минусы                                                                 |
| -------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **react-i18next**    | Индустриальный стандарт для React. Плюрализация, интерполяция, неймспейсы, ICU, бандлы, TS.    | Требует `i18next` как зависимость (~10KB gzip).                        |
| **react-intl**       | FormatJS экосистема. Отличная поддержка ICU MessageFormat.                                     | Тяжелее (~25KB). Избыточен для first-party плагинов.                   |
| **lingui**           | Макросы для compile-time извлечения строк.                                                     | Требует отдельного шага сборки. Сложная интеграция в монорепо.         |
| **Самописный**       | Полный контроль, 0 зависимостей.                                                               | Нет плюрализации, интерполяции, ICU. Придётся писать всё руками.       |
| **Текущий (data-i18n)** | Уже работает на лендинге.                                                                     | Не масштабируется (см. §2.1).                                          |

**Выбор: `i18next` + `react-i18next`**

Причины:
- Стандарт де-факто для React-экосистемы.
- Единый фреймворк для лендинга (Vanilla `i18next`) и приложения (`react-i18next`).
- JSON-словари в файлах — совместимость с co-location-принципом.
- Плюрализация «из коробки» (русский: 1/2-4/5+, английский: 1/other).
- TypeScript-типизация через `i18next-resources-for-ts`.
- Интерполяция: `t('welcome', { name: user.name })`.
- Поддержка бандлов/чанков для отложенной загрузки переводов больших плагинов (опционально).

### 4.2. Структура файлов локализации (co-location)

Каждый пакет хранит свои переводы **рядом с кодом** — в папке `i18n/` внутри пакета. Это соответствует принципу 5 из `ARCHITECTURE_VISION.md` («UI, логика, контент, i18n, тесты — в одной папке»).

```
apps/landing/
  i18n/
    en.json          ← переводы лендинга (EN)
    ru.json          ← переводы лендинга (RU)

apps/web/
  i18n/
    en.json          ← общие UI-строки приложения: шапка, футер, 404, диалоги
    ru.json

packages/plugins/theory-scales/
  i18n/
    en.json          ← переводы плагина Scales
    ru.json

packages/plugins/ear-training/
  i18n/
    en.json
    ru.json

packages/shared/
  i18n/
    en.json          ← общие строки: кнопки «Отмена»/«Сохранить», названия стилей, дни недели
    ru.json

apps/api/
  i18n/
    templates/
      en/
        magic-link.html   ← email-шаблоны на английском
        welcome.html
      ru/
        magic-link.html   ← email-шаблоны на русском
        welcome.html
```

### 4.3. Именование ключей

Формат: `section.element[.variant]` — наследует подход лендинга, но сгруппирован по неймспейсам.

```json
// apps/landing/i18n/en.json
{
  "nav": {
    "features": "Features",
    "how": "How it works"
  },
  "hero": {
    "h1": "Let your music take flight.",
    "sub": "Learn to improvise with a virtual band...",
    "badge": "Browser-based · Free to start"
  },
  "cta": {
    "tryFree": "Try it free",
    "watchDemo": "Watch demo"
  }
}
```

```json
// packages/plugins/theory-scales/i18n/en.json
{
  "page": {
    "title": "Scales",
    "description": "Interactive scale reference"
  },
  "selector": {
    "label": "Select scale",
    "placeholder": "Choose a scale..."
  },
  "scale": {
    "ionian": "Ionian (Major)",
    "dorian": "Dorian",
    "mixolydian": "Mixolydian"
  }
}
```

**Правила:**
- **Вложенные объекты** — не плоский список. Глубина ≤ 3 уровня.
- **camelCase** для ключей-листьев (`tryFree`, а не `try-free`).
- **Неймспейс верхнего уровня** совпадает с именем пакета (`nav`, `hero`, `page`, `selector`).
- **Общие ключи** (Cancel/Save/Loading/Error) — в `@jazz/shared/i18n/`.

### 4.4. Интеграция в плагинную модель

#### Инициализация i18next (shell-level)

`apps/web` инициализирует единый инстанс `i18next` на всё приложение:

```ts
// apps/web/src/i18n/init.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';

// Импортируем словари из всех пакетов (сборщик мёртвый код удалит)
import landingEn from '@jazz/landing/i18n/en.json';
import landingRu from '@jazz/landing/i18n/ru.json';
import sharedEn from '@jazz/shared/i18n/en.json';
import sharedRu from '@jazz/shared/i18n/ru.json';
// ...импорты плагинов добавляются шаблонно

await i18n.use(initReactI18next).init({
  resources: {
    en: {
      landing: landingEn,
      shared: sharedEn,
      // plugin namespaces are loaded lazily or statically
    },
    ru: {
      landing: landingRu,
      shared: sharedRu,
    },
  },
  lng: detectLanguage(), // см. §4.5
  fallbackLng: 'en',
  defaultNS: 'shared',
  interpolation: { escapeValue: false }, // React already escapes
});
```

#### Использование в плагине

```tsx
// packages/plugins/theory-scales/src/ScalesPage.tsx
import { useTranslation } from 'react-i18next';

function ScalesPage() {
  const { t } = useTranslation('theory-scales');

  return (
    <div>
      <h1>{t('page.title')}</h1>
      <select aria-label={t('selector.label')}>
        <option>{t('selector.placeholder')}</option>
        {scales.map((s) => (
          <option key={s}>{t(`scale.${s}`, s)}</option>
        ))}
      </select>
    </div>
  );
}
```

#### Типизация ключей

Через `i18next-resources-for-ts` генерируются типы из JSON-файлов:

```ts
// typesafe-i18n.d.ts
import 'i18next';
import type landing from '@jazz/landing/i18n/en.json';
import type shared from '@jazz/shared/i18n/en.json';

declare module 'i18next' {
  interface CustomTypeOptions {
    resources: {
      landing: typeof landing;
      shared: typeof shared;
      // ...каждый плагин добавляет свой неймспейс
    };
  }
}
```

После этого `t('hero.h1')` проверяется TypeScript'ом — опечатка в ключе подсветится.

### 4.5. Определение языка

**Приоритет выбора (совпадает с лендингом):**

1. Сохранённый выбор пользователя (localStorage → `jazz-lang`)
2. Настройка из профиля пользователя (API → `settings.locale`)
3. Browser language (`navigator.language`)
4. Fallback: `en`

**Переключение языка:**
- **Лендинг:** switcher EN/RU в шапке (уже есть). При клике — `i18next.changeLanguage()` + `localStorage.setItem('jazz-lang')`.
- **Приложение:** Переключатель в `/settings` (для залогиненных) + автоопределение для незалогиненных. Смена языка = мгновенный ререндер всего UI через `i18next.react`.

**API-эндпоинт для сохранения языка:**

```ts
// apps/api/src/routes/settings.routes.ts — добавить поле locale
PATCH /api/settings
Body: { locale: 'en' | 'ru' }
```

### 4.6. Лендинг: миграция на i18next

Текущий подход на `data-i18n` заменяется на `i18next`:

```ts
// apps/landing/src/i18n.ts
import i18n from 'i18next';
import en from '../i18n/en.json';
import ru from '../i18n/ru.json';

await i18n.init({
  resources: { en: { translation: en }, ru: { translation: ru } },
  lng: detectLanguage(), // та же логика: localStorage → browser → 'en'
  fallbackLng: 'en',
});

export default i18n;
```

```ts
// apps/landing/src/main.js
import i18n from './i18n';

i18n.on('languageChanged', () => {
  document.documentElement.lang = i18n.language;
  document.querySelectorAll('[data-i18n]').forEach((el) => {
    el.textContent = i18n.t(el.dataset.i18n);
  });
});
```

HTML-разметка не меняется — `data-i18n` атрибуты остаются, но текст теперь берётся из JSON-файла через `i18next.t()`.

### 4.7. API: локализация email-шаблонов

Email-шаблоны хранятся как HTML-файлы в `apps/api/i18n/templates/<lang>/`. Выбор шаблона — по полю `locale` из профиля пользователя в БД.

```ts
// apps/api/src/services/email.service.ts (упрощённо)
import { readFileSync } from 'fs';
import path from 'path';

function loadTemplate(name: string, locale: string): string {
  const filePath = path.resolve(__dirname, `../i18n/templates/${locale}/${name}.html`);
  return readFileSync(filePath, 'utf-8');
}

export async function sendMagicLink(email: string, link: string, locale: string) {
  const html = loadTemplate('magic-link', locale)
    .replace('{{link}}', link)
    .replace('{{email}}', email);

  return emailProvider.send({ to: email, subject: i18nSubject(locale), html });
}
```

### 4.8. Даты, числа, валюты

Используем `Intl` API браузера (0 зависимостей, поддержка всех современных браузеров):

```ts
// packages/plugin-sdk/src/hooks/useLocale.ts
import { useTranslation } from 'react-i18next';

export function useLocale() {
  const { i18n } = useTranslation();
  return i18n.language; // 'en' | 'ru'
}

// Использование:
const locale = useLocale();
new Date(ts).toLocaleDateString(locale);
price.toLocaleString(locale, { style: 'currency', currency: 'USD' });
```

Заменяем все хардкодженные `'ru-RU'` на значение из `i18n.language`.

## 6. Допущения и риски

### Допущения (assumptions)

1. **[assumption] Только EN и RU на старте.** Другие языки (ES, PT, FR, DE, JA) — out of scope этой версии. Архитектура (JSON-словари, i18next) позволяет добавить их позже без переписывания.
2. **[assumption] Переключение языка — мгновенное.** Без перезагрузки страницы. i18next это поддерживает (react-rebind всех `useTranslation` хуков). Не требует SSR.
3. **[assumption] Аккордовая нотация не переводится.** Пользователи джаза читают `Cmaj7`, а не `До_маж7`. Если потребуется — обсуждается отдельно.
4. **[assumption] Email-язык определяется по `settings.locale`, а не по браузеру.** Пользователь, выбравший RU в приложении, получает RU-письма.
5. **[assumption] Неймспейсы плагинов статически импортируются.** Lazy-load бандлов (`i18next-http-backend`) не нужен для first-party плагинов, где словари крошечные (30–80 ключей).

### Риски

| Риск                                                                                                       | Вероятность | Влияние | Митигация                                                                   |
| ---------------------------------------------------------------------------------------------------------- | ----------- | ------- | --------------------------------------------------------------------------- |
| **Расхождение ключей между языками.** RU-файл имеет ключ, EN-файл — нет → `t()` возвращает ключ как строку | Средняя     | Низкое  | TypeScript-типы ловят на CI. ESLint-правило `i18next/no-literal-string`.    |
| **Большой объём рутины: 16 плагинов × 2 языка.**                                                           | Высокая     | Среднее | Механический экстракт из JSX → JSON (скрипт). Линтер проверяет полноту.    |
| **Конфликт неймспейсов.** Плагин `ear-training` и `shared` имеют ключ `play` с разным смыслом              | Низкая      | Среднее | Неймспейсы изолированы. `t('ear-training:play')` vs `t('shared:play')`.     |
| **Сопротивление команды.** «Зачем переводить, если мы все русскоязычные?»                                  | Средняя     | Высокое | Рынок англоязычного джазового EdTech — основной. Без EN — нет роста.        |
| **Навигация плагинов (`navItems`) не переводится динамически.** Лейблы в манифесте статичны               | Высокая     | Среднее | `label` в манифесте = ключ для `t()`. Или shell подставляет перевод сам.    |

## 7. Что не войдёт (Out of Scope)

- **Больше 2 языков.** Только EN + RU на старте.
- **RTL-языки** (арабский, иврит). Нет в ближайших планах.
- **Локализация content-сеток.** Названия джазовых стандартов (`Autumn Leaves`) не переводятся.
- **Локализация AI-ассистента.** AI-ответы генерируются на языке запроса — это поведение модели, не наш код. [assumption]
- **Локализация аудио-контента.** Сэмплы, метроном, голосовые подсказки — язык не применим.
- **Локализация админки в полном объёме.** Администраторы — русскоязычная команда. EN — «для галочки» на P3.
