# MOBILE — Мобильное представление Jazz Trainer

> **Статус:** Требования (спецификация)
> **Цель:** Адаптивный веб для планшета и смартфона. Подготовка к React Native.
> **Целевая платформа:** Chromium / Chrome (Web Audio API, Web MIDI API)
> **Автор:** software-engineer AI agent
> **Дата:** 2026-07-26

---

## 1. Принципы

1. **Плагины не знают про устройство.** Ни один плагин не должен содержать `window.innerWidth`, media-query breakpoints, или условную логику «если мобильный». Адаптивность — зона ответственности shell и/или общего UI-кита (`@jazz/ui`). Плагины не импортируют `apps/web`.

2. **Shell адаптирует, плагин — наполняет.** Shell предоставляет layout (колонки, drawer, bottom-tabs), а плагин рендерит контент в `<Outlet />`. Если экрану нужна принципиально иная компоновка для mobile — создаётся **mobile-вариант shell**, а не условие внутри плагина.

3. **Chrome/Chromium — единственная цель.** Web Audio API (`AudioContext`, `OfflineAudioContext`), Web MIDI API, `navigator.requestMIDIAccess()` — всё это работает только в Chromium-based браузерах. Не тратим ресурсы на Firefox/Safari-совместимость.

4. **Прогрессивное улучшение.** Десктоп — полный набор. Планшет — близко к десктопу с упрощениями. Смартфон — выборочный набор функций, сфокусированный на потреблении и простых действиях. Администрирование — мониторинг + критические toggle-действия на смартфоне.

5. **Touch-first для смартфона.** Все интерактивные элементы ≥ 44×44px (WCAG 2.1). Жесты (свайп, pinch) там, где они уместны. MIDI-ввод на смартфоне — через виртуальную клавиатуру или tap-пэд, а не физическое устройство.

6. **Готовим к React Native, но не сейчас.** Компоненты пишутся так, чтобы логика была отделена от представления. Никаких инлайн-стилей с пикселями, зависимых от браузерного viewport. Используем CSS-переменные и абстракцию от медиа-запросов (через `@jazz/ui`).

## 2. Breakpoints и классификация устройств

| Категория       | Ширина (CSS px) | Типовое устройство    | Ориентация          |
| --------------- | --------------- | --------------------- | ------------------- |
| **Phone**       | 320–767         | iPhone SE, Pixel 7    | Портрет (приоритет) |
| **Phone wide**  | 568–767         | iPhone SE, Pixel 7    | Ландшафт            |
| **Tablet**      | 768–1023        | iPad Mini, Galaxy Tab | Портрет             |
| **Tablet wide** | 1024–1279       | iPad Air/Pro, Surface | Ландшафт            |
| **Desktop**     | ≥ 1280          | Ноутбук, монитор      | —                   |

**Breakpoint-переменные (CSS custom properties):**

```css
:root {
  --bp-phone: 320px;
  --bp-phone-wide: 568px;
  --bp-tablet: 768px;
  --bp-tablet-wide: 1024px;
  --bp-desktop: 1280px;
}
```

**Принцип выбора макета:**

- `< 768px` — **Phone layout** (одноколоночный, bottom-tab навигация, drawer для меню)
- `768–1279px` — **Tablet layout** (двухколоночный где возможно, боковая панель, полноценная навигация как на десктопе с уменьшенными элементами)
- `≥ 1280px` — **Desktop layout** (текущий, без изменений)

## 3. Общие паттерны навигации и Shell'ов

### 3.1. Phone (< 768px)

**Навигация — Bottom Tab Bar:**

```
┌──────────────────────────────────┐
│ Header (48px, лого + аватар)     │
├──────────────────────────────────┤
│                                  │
│  Контент (Outlet)                │
│                                  │
├──────────────────────────────────┤
│ 🏠Каталог │ 🎓Теория │ 🎯Практ.│ ⋯Ещё  │  ← 48px, фиксирован
└──────────────────────────────────┘
```

- **5 табов максимум**: Каталог, Теория, Упражнения, Ещё (drawer), Профиль.
- **Ещё** открывает **Drawer (слева)** с полным списком разделов:
  - Ear Training, Rhythm Drills, Chord Quiz, Progression Recognition
  - Администрирование (только если есть роль admin)
  - Настройки, Профиль
- **Header** — уменьшенный: высота 48px (вместо 96px). Логотип-иконка без текста «Jazz Trainer». Аватар справа. Без горизонтального меню.
- **Жест:** свайп от левого края → Drawer. Свайп вправо по контенту → назад (стек навигации).

**Типы Shell для Phone:**

| Desktop Shell | Phone Shell         | Описание                                                             |
| ------------- | ------------------- | -------------------------------------------------------------------- |
| `AppShell`    | `MobileAppShell`    | Header 48px + контент + BottomTab                                    |
| `EditorShell` | `MobileEditorShell` | Header 48px (с кнопкой Назад) + полноэкранный контент, без BottomTab |
| `AdminShell`  | `MobileAdminShell`  | Header 48px + список разделов + контент, без BottomTab               |

### 3.2. Tablet (768–1279px)

- Сохраняет **Header 64px** с горизонтальной навигацией (упрощённой: меньше пунктов, иконки + текст).
- **Sidebar** (200–240px) заменяет BottomTab там, где это оправдано:
  - **AppShell:** нет sidebar, используется Header-навигация как на десктопе.
  - **AdminShell:** левый sidebar как на десктопе, но уже (220px вместо 260px).
  - **EditorShell:** без sidebar (как десктоп).
- Двухколоночные макеты где уместно: каталог (сетка карточек 2 колонки), теория (список + контент).
- BottomTab не используется на планшете.

### 3.3. Таблица: Категории плагинов → мобильный шаблон

| Категория     | Phone (< 768px)                                            | Tablet (768–1279px)                                      |
| ------------- | ---------------------------------------------------------- | -------------------------------------------------------- |
| `core`        | EditorShell (редактор/плеер), AppShell (каталог/настройки) | EditorShell / AppShell (как десктоп с адаптацией ширины) |
| `theory`      | AppShell + drawer-список лекций                            | AppShell: sidebar-список + контент                       |
| `practice`    | MobileEditorShell (полноэкранный)                          | EditorShell (как десктоп)                                |
| `assess`      | MobileEditorShell (полноэкранный)                          | EditorShell (как десктоп)                                |
| `play`        | MobileEditorShell (полноэкранный)                          | EditorShell (как десктоп)                                |
| `instruments` | 🟡 Нет UI (инструменты — аудио-плагины, не страницы)       | —                                                        |
| `admin`       | MobileAdminShell: read-only список + мониторинг (см. §8)   | AdminShell с узким sidebar                               |

## 4. Поэкранные требования

### 4.1. Каталог (`/`, `/my`) — Плагин `catalog`

**Desktop:** Сетка карточек 3-колонки + поиск + фильтры слева.

| Устройство | Макет                                                                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Phone**  | 1 колонка. Поиск — sticky сверху. Фильтры — в drawer (по тапу на иконку фильтра). Карточки — полноширинные с крупным превью. Свайп влево/вправо по карточке: лайк / копировать. |
| **Tablet** | 2 колонки. Фильтры — компактный ряд чипов под поиском. Карточки — как на десктопе, но в 2 колонки.                                                                              |

**Phone-специфика:**

- Pull-to-refresh для обновления каталога.
- Бесконечный скролл (не пагинация).
- Карточка: обложка (полноширинная, 16:9), название, стиль, BPM, автор. Кнопка «Играть» — крупная (48px), по центру карточки.
- Тап по карточке → страница сетки (EditorShell).

### 4.2. Редактор сетки (`/compositions/:id`) — Плагин `core-editor`

**Desktop:** DSL-редактор + piano-roll + панель свойств. Три панели.

**Tablet (`≥1024px`):**

- 2 панели: DSL-редактор (слева, 60%) + панель свойств / клавиатура (справа, 40%).
- Piano-roll скрыт, открывается по кнопке «Piano Roll» — заменяет правую панель.

**Phone:**

- **Только DSL-ввод** (textarea). Никакого piano-roll, никакой панели свойств в основном виде.
- Над textarea — **toolbar с чипами**: «+ |», «Добавить аккорд», «DSL-помощь», «Свойства».
- Тап «Свойства» → fullscreen-панель с метаданными сетки (название, BPM, размер, стиль).
- Тап «Добавить аккорд» → bottom sheet с chord palette (поиск/выбор аккорда) — вставляет символ аккорда в DSL.
- **DSL-помощь** — bottom sheet с шпаргалкой DSL-синтаксиса.
- Автоскролл textarea при вводе.
- Клавиатура: **не показывать** системную клавиатуру при фокусе textarea. Использовать кастомную **chord-input панель** в нижней части экрана (клавиши: ноты, бемоль/диез, цифры, maj/min/dim/aug, 7/9/11/13). Это компромисс: ввод медленнее, но без системной клавиатуры, которая скрывает контент.

### 4.3. Плеер (`/play`, `/play/:id`) — Плагин `core-player`

**Desktop:** Транспорт-панель + гармоническая сетка + настройки громкости.

**Phone:**

- **Полноэкранный режим.** Header исчезает через 3 сек (тап — показать).
- Гармоническая сетка: горизонтальный скролл с текущим баром по центру (автоскролл при воспроизведении).
- Транспорт-панель: **фиксирована снизу**, 72px.
  - Кнопки: Stop, Play/Pause (крупная, 56px в центре), Loop.
  - BPM: отображается, тап → ползунок в bottom sheet.
- **Жесты:**
  - Свайп влево/вправо по сетке — перемотка по тактам.
  - Двойной тап — play/pause.
  - Свайп вверх по транспорт-панели — bottom sheet с громкостями инструментов.
- **Портрет vs ландшафт:**
  - Портрет: сетка — узкая полоса (1 такт = ширина экрана), остальное — транспорт.
  - Ландшафт: сетка — шире (2–4 такта), транспорт компактнее.

**Tablet:**

- Гармоническая сетка + транспорт как на десктопе, но транспорт-панель — фиксирована снизу (не плавающая). Высота: 80px.
- Громкости — боковая панель справа (сворачиваемая).

### 4.4. Настройки аранжировки (`/settings`) — Плагин `core-settings`

**Desktop:** Таблица стиль × инструмент + селекторы.

**Phone:**

- **Список, не таблица.** Каждый инструмент — аккордеон (collapsed по умолчанию).
- Стиль — верхний селектор (горизонтальный скролл чипов).
- Внутри аккордеона — вертикальный список per-style настроек.
- **Соло-инструмент** и **MIDI-устройство** — отдельные секции внизу.
- Кнопка «Сохранить» — фиксирована снизу (чтобы не скроллить ради неё).

**Tablet:**

- Таблица как на десктопе, но с горизонтальным скроллом (sticky первый столбец — название инструмента).
- Стиль — горизонтальный scrollable ряд табов.

### 4.5. Теория (`/theory` и подразделы) — Плагины `theory-*` (22 шт.)

**Desktop:** Каталог `/theory` + отдельные страницы для каждой лекции.

**Phone:**

- **Каталог:** 1 колонка, крупные карточки. Поиск sticky сверху.
- **Лекция:** Полноэкранный режим. Содержимое лекции с вертикальным скроллом.
  - Интерактивные элементы (визуализация аккордов на клавиатуре) — упрощённая мини-клавиатура (1 октава).
  - Аудио-примеры — кнопка Play крупная (48×48).
  - Кнопка «Назад к каталогу» — в Header.
- **Навигация между лекциями:** свайп влево/вправо (если открыты из каталога).

**Tablet:**

- **Split-view:** слева (30%) — список лекций, справа (70%) — содержимое выбранной.
- Идеально для учебного процесса: видишь структуру и контент одновременно.

### 4.6. Упражнения (`/practice-cards`) — Плагин `practice-cards`

**Desktop:** Телесуфлёр с карточками, сменяющимися по тактам.

**Phone:**

- **Полноэкранный режим** (MobileEditorShell). Без BottomTab.
- **Карточка — на весь экран.** 1 карточка одновременно (не 1/2/3 как на десктопе).
- Анимация: карточка сдвигается вверх (не влево — вертикальный скролл естественнее на телефоне).
- **Count-in:** 4 крупных точки по центру экрана, загораются по очереди.
- **Жест:** свайп вниз — прервать упражнение (вернуться к настройкам).
- Настройка упражнения (3-шаговый мастер) — на отдельных экранах с кнопкой «Далее» (step-by-step wizard), не на одном scrollable экране.

**Tablet:**

- 2 карточки одновременно (текущая + следующая).
- Анимация slide-left как на десктопе.
- Count-in: точки сверху.
- Мастер настройки — в sidebar (слева 250px), предпросмотр — справа.

### 4.7. Тренировка слуха (`/ear-training`) — Плагин `ear-training`

**Desktop:** Выбор интервалов + MIDI-ввод + результат.

**Phone:**

- **Полноэкранный режим.** Header — «Ear Training» + кнопка «Назад».
- **Ввод нот без MIDI-клавиатуры:**
  - **Вариант А (основной):** Виртуальная клавиатура — мини-клавиатура (1.5 октавы) в нижней части экрана. Клавиши ≥ 44px шириной.
  - **Вариант Б:** Tap-пэд — пользователь нажимает на зоны (низкая/средняя/высокая нота), проверяется только направление интервала.
- **Настройки сложности:** Bottom sheet (тянем вверх за handle).
- **Результат:** после каждого ответа — анимация ✅/❌ и правильный ответ.
- **Прогресс:** шкала сверху (X из Y правильно).

**Tablet:**

- Виртуальная клавиатура + визуализация. Поддержка физической MIDI-клавиатуры.
- Split: слева клавиатура/ноты, справа настройки и результат.

### 4.8. Ритм (`/rhythm-drills`) — Плагин `rhythm-drills`

**Phone:**

- **Tap-зона** — крупная (≥ 120×120px), по центру экрана. Один большой «пэд».
- Ритмический паттерн визуализируется сверху (точки/полоски).
- Метроном — визуальная пульсация фона + звук.
- **Результат:** точность попадания в долю — цветовая индикация (зелёный/жёлтый/красный).

**Tablet:**

- Два пэда (левый/правый) для различения сильной/слабой доли.
- Визуализация ритма как на десктопе.

### 4.9. Квизы (`/chord-quiz`, `/progression-recognition`) — Плагины `chord-quiz`, `progression-recognition`

**Phone:**

- 1 вопрос на экран. Крупный текст.
- Варианты ответов — кнопки во всю ширину (≥ 48px высота).
- Тап → мгновенная обратная связь (правильно/неправильно) → авто-переход к следующему через 1 сек.
- Прогресс-бар сверху: вопрос X из Y.

**Tablet:**

- Как десктоп — 1 вопрос + 4 варианта.

### 4.10. MIDI-клавиатура (`/visual-midi-keyboard`) — Плагин `visual-midi-keyboard`

**Phone:**

- Интегрируется в другие экраны (ear-training, practice-cards) как нижняя панель.
- Как отдельная страница не имеет смысла на телефоне — **скрыть из навигации** на `< 768px`.

**Tablet:**

- Нижняя панель клавиатуры (1.5 октавы). Взаимодействие — тап по клавишам (touch=noteOn).

## 5. Touch, ввод и MIDI-альтернативы

### 5.1. Touch-взаимодействие

| Жест                 | Действие                                   | Где применяется   |
| -------------------- | ------------------------------------------ | ----------------- |
| Тап                  | Выбор, play/pause, активация               | Везде             |
| Двойной тап          | Play/pause (в плеере), zoom                | Плеер, каталог    |
| Свайп влево/вправо   | Перемотка тактов, навигация между лекциями | Плеер, теория     |
| Свайп вверх/вниз     | Открыть/закрыть bottom sheet               | Плеер, настройки  |
| Свайп от левого края | Открыть drawer                             | Phone (везде)     |
| Pinch                | Масштаб (piano-roll на планшете)           | Планшет, редактор |
| Long press           | Контекстное меню                           | Каталог, сетка    |

### 5.2. MIDI без физического устройства

На смартфоне физическая MIDI-клавиатура — редкий сценарий. Нужны альтернативы:

| Альтернатива               | Применение                   | Механика                                                                                                                 |
| -------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **Виртуальная клавиатура** | Ear training, practice-cards | Горизонтальная полоса клавиш (1–1.5 октавы) внизу экрана. Тап по клавише = noteOn. Фиксированная зона ≥ 44px на клавишу. |
| **Tap-пэд**                | Rhythm drills                | Одна/две крупные зоны тапа. Отслеживание времени между тапами = ритм.                                                    |
| **Выбор из списка**        | Chord quiz, progression      | Кнопки-варианты. Не требует MIDI.                                                                                        |

### 5.3. Виртуальная клавиатура (Phone)

Минимальная реализация для `< 768px`:

- **1 октава** с кнопкой сдвига влево/вправо. Или **1.5 октавы** скроллируемые.
- Белые клавиши: ширина ≥ 44px, высота ≥ 120px.
- Чёрные клавиши: ширина ≥ 28px, высота ≥ 72px.
- Мультитач не обязателен (в учебных целях играют одну ноту за раз).
- Визуальная обратная связь: клавиша «загорается» при тапе.

**Не использовать:** системную клавиатуру для ввода нот. Только кастомные chord-input панели.

### 5.4. Системная клавиатура

Единственное место, где системная клавиатура **допустима**:

- Текстовые поля: название композиции, поиск по каталогу, логин/пароль.
- **Не** для ввода нот, аккордов, DSL.

## 7. Admin на смартфоне: компромиссы

Администрирование на смартфоне — **мониторинг + критические toggle-действия**. Полноценное администрирование (конструкторы, сложные формы) — только на планшете/десктопе.

**Разрешённые мутации:** блокировка/разблокировка пользователя, смена роли, toggle feature flag, скрыть/показать контент, удаление (с подтверждением), загрузка одного файла.
**Запрещено:** конструкторы (piano/drum/percussion/bass/rhodes), массовые операции, редактирование JSON/YAML-конфигураций.

### 7.1. Что доступно на Phone

| Раздел                                        | Действия                                                                                |
| --------------------------------------------- | --------------------------------------------------------------------------------------- |
| **Пользователи** (`admin-users`)              | Список. Поиск. Блокировка/разблокировка (swipe action). Смена роли (выпадающий список). |
| **Роли** (`admin-roles`)                      | Список ролей с permissions. Read-only.                                                  |
| **Контент** (`admin-content`)                 | Список сеток. Поиск. Скрыть/показать (toggle). Удалить (swipe + confirm).               |
| **Feature flags** (`admin-flags`)             | Список флагов. Включить/выключить (toggle switch).                                      |
| **Ассеты** (`admin-assets`)                   | Список. Загрузка (кнопка «+») — выбор из файловой системы. Удалить (swipe).             |
| **Диагностика** (`admin-diagnostics`)         | Audit log (список, scroll). Health-check (зелёный/красный индикатор).                   |
| **Настройки по умолчанию** (`admin-defaults`) | Аккордеон-список как `/settings`. Сохранить.                                            |
| **Упражнения** (`admin-exercises`)            | Список. Включить/выключить. Переименовать (inline edit).                                |
| **Теория** (`admin-theory`)                   | Список лекций. Включить/выключить. Порядок (drag handle).                               |

### 7.2. Недоступно на Phone (скрыть из навигации)

Все **конструкторы** требуют точного визуального редактирования (piano-roll, step-grid) и нереализуемы на экране < 428px:

- `admin-piano-constructor`
- `admin-drum-constructor`
- `admin-percussion-constructor`
- `admin-bass-constructor`
- `admin-rhodes-constructor`

На Phone эти пункты **скрыты из Drawer**. При попытке прямого перехода по URL — показывается заглушка: «Этот раздел доступен только на планшете или компьютере».

### 7.3. Tablet Admin

- Все разделы доступны.
- Конструкторы — с адаптированным layout:
  - Piano/Drum/Bass/Rhodes: piano-roll/step-grid занимает 100% ширины, панель инструментов — bottom sheet.
  - Упрощённые контролы: крупнее кнопки, меньше текстовых инпутов.

## 8. Chrome/Chromium — специфичные требования

### 8.1. Feature Detection

При загрузке приложения — детектировать:

```ts
const hasWebAudio =
  typeof AudioContext !== 'undefined' || typeof webkitAudioContext !== 'undefined';
const hasWebMidi = typeof navigator.requestMIDIAccess === 'function';
const hasOfflineAudio = typeof OfflineAudioContext !== 'undefined';

if (!hasWebAudio || !hasOfflineAudio) {
  // Показать экран-заглушку: «Jazz Trainer требует браузер с поддержкой Web Audio API (Chrome, Edge, Opera)»
}
```

**Почему фича-детект, а не браузер-детект:** `window.chrome` есть в Opera и Edge; некоторые Android-браузеры на Chromium не имеют этого свойства. Важно наличие API, а не бренд браузера.

### 8.2. AudioContext Policy

- `AudioContext` создаётся **только после первого user gesture** (тап/клик). На mobile это критично — iOS/Safari не актуальны, но Chrome Android имеет ту же политику.
- Стартовый экран: «Нажмите, чтобы начать» → резюмирует AudioContext.

### 8.3. Web MIDI на Android

- Chrome Android **не поддерживает** Web MIDI API (на 2026 год — маловероятно, но проверяем). Вместо физического MIDI используется виртуальная клавиатура/tap-пэд (§5.2).
- На планшетах с Chrome OS — Web MIDI работает.

### 8.4. Viewport и масштабирование

```html
<meta
  name="viewport"
  content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no"
/>
```

- `user-scalable=no` — предотвращает случайный zoom при двойном тапе. Для доступности: кнопка «A+» в настройках для крупного шрифта.
- `maximum-scale=1` — предотвращает zoom при фокусе input (Chromium Android).

### 8.5. PWA-хук (подготовка)

Не цель текущей фазы, но закладываем:

- `manifest.json` в `apps/web/public/` с `display: standalone`, иконками 192/512px.
- Service Worker для offline-кеширования статики (не для аудио — сэмплы слишком большие).
- Аудио-сэмплы остаются сетевыми (CDN). Кеширование через Cache-Control, а не SW.

## 9. Путь к React Native (черновик видения)

> **Статус:** Видение, не архитектурное решение. Будет оформлено как ADR-018 при переходе к реализации.
> **Текущая фаза:** адаптивный Web (этот документ). React Native — за горизонтом планирования.

### 9.1. Текущая фаза (Адаптивный Web)

- Все требования этого документа — про адаптивный веб (CSS media queries, responsive layout).
- React Native **не используется**. Никакого `react-native` в зависимостях.
- Но код пишется с учётом будущей миграции.

### 9.2. Принципы, облегчающие миграцию

| Принцип                       | Как достигается сейчас                                                                                                    |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Отделение логики от UI        | Бизнес-логика в `music-core` и `shared`. Плагины — тонкая прослойка над `@jazz/plugin-sdk`. UI-компоненты — в `@jazz/ui`. |
| Абстракция медиа-запросов     | Хук `useBreakpoint()` в `@jazz/ui`, не `window.matchMedia` напрямую.                                                      |
| Компоненты без браузерных API | Все обращения к Audio/MIDI — через адаптеры. Плагины не используют `navigator`, `AudioContext`.                           |
| Стили через переменные        | CSS custom properties + Tailwind-классы. Никаких инлайн-пикселей, привязанных к десктопу.                                 |
| Навигация — конфигурация      | Роуты определены в плагин-манифесте декларативно. Shell рендерит.                                                         |

### 9.3. Что изменится при переходе на React Native

| Сейчас (Web)                         | Будет (React Native)                                                        |
| ------------------------------------ | --------------------------------------------------------------------------- |
| `react-router-dom`                   | `@react-navigation/native`                                                  |
| CSS + Tailwind                       | StyleSheet / Tamagui                                                        |
| HTML `<input>`, `<textarea>`         | RN `<TextInput>`                                                            |
| Web Audio API → `tone-audio-adapter` | `expo-audio` или нативный модуль → новый адаптер                            |
| Web MIDI API → `webmidi-adapter`     | `react-native-midi` или CoreMIDI (iOS) / USB MIDI (Android) → новый адаптер |
| Виртуальная клавиатура (DOM)         | React Native кастомный View                                                 |
| Bottom sheet (CSS)                   | `@gorhom/bottom-sheet`                                                      |

**Ключевое:** замена только адаптеров и shell. Плагины не меняются.

## 10. Техническая реализация

### 10.1. Новые компоненты в `apps/web/src/components/layout/`

| Компонент               | Назначение                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------- |
| `MobileDrawer`          | Боковое меню-шторка для Phone                                                                            |
| `BottomTabBar`          | Нижняя панель табов (Phone)                                                                              |
| `MobileHeader`          | Уменьшенный Header 48px (Phone)                                                                          |
| `MobileAppShell`        | Layout: MobileHeader + BottomTabBar + Outlet                                                             |
| `MobileEditorShell`     | Layout: MobileHeader (назад) + полноэкранный Outlet                                                      |
| `MobileAdminShell`      | Layout: MobileHeader + scrollable список + Outlet                                                        |
| `TabletAppShell`        | Layout: Header 64px + контент + опциональный sidebar                                                     |
| `TabletAdminShell`      | Layout: Header + узкий sidebar + контент                                                                 |
| `MobileVirtualKeyboard` | Touch-клавиатура для MIDI-ввода (Phone/Tablet). Адаптация существующего `VirtualKeyboard`. В `@jazz/ui`. |
| `TapPad`                | Крупная зона тапа для ритма (Phone). В `@jazz/ui`.                                                       |
| `BottomSheet`           | Переиспользуемый bottom sheet. В `@jazz/ui`.                                                             |

### 10.2. Хук `useBreakpoint()` в `@jazz/ui`

```ts
// packages/ui/src/hooks/useBreakpoint.ts
type Breakpoint = 'phone' | 'phone-wide' | 'tablet' | 'tablet-wide' | 'desktop';

function useBreakpoint(): Breakpoint {
  // Следит за window.innerWidth, возвращает текущий breakpoint.
  // Кеширует результат для избежания лишних ре-рендеров.
  // Использует matchMedia для производительности.
}
```

**Важно:** хук используется **только в Shell (`apps/web`) и UI-компонентах `@jazz/ui`**. Плагинам импорт `useBreakpoint` запрещён ESLint-правилом `no-restricted-imports`. Плагины не должны знать breakpoint — адаптивность достигается сменой Shell, а не условной логикой внутри плагина.

### 10.3. Выбор Shell по breakpoint в `App.tsx`

```tsx
function AdaptiveShell({
  type,
  children,
}: {
  type: 'app' | 'editor' | 'admin';
  children: React.ReactNode;
}) {
  const bp = useBreakpoint();

  if (bp === 'phone' || bp === 'phone-wide') {
    switch (type) {
      case 'app':
        return <MobileAppShell>{children}</MobileAppShell>;
      case 'editor':
        return <MobileEditorShell>{children}</MobileEditorShell>;
      case 'admin':
        return <MobileAdminShell>{children}</MobileAdminShell>;
    }
  }

  if (bp === 'tablet' || bp === 'tablet-wide') {
    switch (type) {
      case 'app':
        return <TabletAppShell>{children}</TabletAppShell>;
      case 'editor':
        return <EditorShell>{children}</EditorShell>; // текущий десктопный
      case 'admin':
        return <TabletAdminShell>{children}</TabletAdminShell>;
    }
  }

  // Desktop — текущее поведение без изменений
  switch (type) {
    case 'app':
      return <AppShell>{children}</AppShell>;
    case 'editor':
      return <EditorShell>{children}</EditorShell>;
    case 'admin':
      return <AdminShell>{children}</AdminShell>;
  }
}
```

### 10.4. Границы слоёв: что не меняется

- **Плагины** — без изменений. Тот же код, тот же `definePlugin()`.
- **music-core** — без изменений. Никакого знания о mobile.
- **shared** — без изменений.
- **plugin-sdk** — без изменений.
- **Адаптеры** — без изменений (Chrome Android поддерживает Web Audio API).
- **apps/web** — новый layout-код в `components/layout/`, адаптивный `App.tsx`.
- **@jazz/ui** — новые компоненты: `MobileVirtualKeyboard` (адаптация существующего `VirtualKeyboard`), `TapPad`, `BottomSheet`, хук `useBreakpoint()`.

**Правило для плагинов:** `useBreakpoint()` недоступен плагинам. Запрещается через ESLint `no-restricted-imports`. Плагины получают адаптивность исключительно через Shell (разные layout для разных breakpoints при одном и том же контенте `<Outlet />`).

## 12. Риски и открытые вопросы

| Риск                                        | Вероятность | Влияние | Смягчение                                                    |
| ------------------------------------------- | ----------- | ------- | ------------------------------------------------------------ |
| Web MIDI не работает на Android Chrome      | Высокая     | Среднее | Виртуальная клавиатура + tap-пэд как альтернатива            |
| Производительность AudioContext на телефоне | Средняя     | Среднее | Упрощённый микс (меньше голосов), отключение Rhodes на Phone |
| Системная клавиатура скрывает контент       | Высокая     | Высокое | Кастомные панели ввода для DSL/аккордов                      |
| Конструкторы невозможны на Phone            | Факт        | Низкое  | Явно исключены из Phone-навигации (§7.2)                     |
| Сэмплы (много мегабайт) на мобильной сети   | Средняя     | Среднее | Lazy-загрузка сэмплов при входе в плеер, индикатор загрузки  |
| 22 плагина теории — много drawer-пунктов    | Низкая      | Низкое  | Группировка в аккордеоны внутри drawer                       |

**Открытые вопросы (требуют решения перед реализацией):**

1. **Chrome Android и AudioContext:** достаточно ли производительности для воспроизведения 5+ голосов (барабаны, бас, фортепиано, Rhodes, соло)? Нужен бенчмарк на реальных устройствах.
2. **Звук через Bluetooth-наушники:** задержка. Нужно ли предупреждение пользователю?
3. **Ландшафтный режим Phone:** поддерживаем ли? (Текущий ответ: да, но макет портрета — приоритет. Ландшафт использует tablet-макет где возможно.)
4. **Фоновое воспроизведение:** должно ли приложение продолжать играть, когда экран заблокирован? (Вероятно нет — учебный процесс требует визуального контакта.)
