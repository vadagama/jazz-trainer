# VISION — AI-ассистент композиций

**Дата:** 2026-07-25
**Горизонт:** MVP (1 версия, ~4–6 недель) → полная версия (~3 месяца)
**Статус:** 🟢 Принято

## 1. Резюме (Executive Summary)

AI-ассистент Amazilia позволяет создавать, изменять и объяснять музыкальные композиции через естественный язык. Пользователь (администратор, а в полной версии — любой музыкант) описывает желаемую композицию словами: «Создай нео-соул в духе ночного джем-сейшена, 82 BPM, Rhodes, мягкий бас, негромкие барабаны» — и получает готовую аранжировку с preview.

Ключевое архитектурное решение: **AI не генерирует финальный объект композиции.** Вместо этого работает цепочка: промпт → исследование → музыкальный замысел → детерминированный компилятор → объект композиции → валидация → предпрослушивание. AI (DeepSeek V4 Flash) отвечает за понимание замысла, стиля и формы; каталог сервиса — единственный источник истины для стилей, инструментов и паттернов; Composition Compiler (TypeScript-код) детерминированно превращает план в объект приложения.

Это делает Amazilia первым веб-тренажёром джазовой гармонии с AI-управляемым созданием аранжировок, не требующим от пользователя знания DSL, теории или внутренних ID паттернов.

**MVP:** Ассистент работает только в админке, оперирует Composition Plan DSL, поддерживает создание/чтение/редактирование композиций, preview и историю версий.

**Полная версия:** Ассистент доступен всем пользователям в интерфейсе аранжировки, поддерживает 4 сценария (создать, изменить, объяснить, предложить), инкрементальные правки через diff, RAG-поиск по базе правил аранжировки и веб-поиск жанровых характеристик.

## 2. Конкурентный контекст

| Продукт                   | AI-ассистент для создания музыки                   | Уровень контроля                                            | Ниша Amazilia                                          |
| ------------------------- | -------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------- |
| **Suno / Udio**           | Генерация полноценных треков по тексту             | Низкий — «чёрный ящик», готовый аудиофайл                   | Генерация аудио, а не аранжировки с разделёнными дорожками |
| **AIVA**                  | AI-композиция в стиле классики/кино                | Средний — нотный редактор                                   | Нет джазовой специализации, нет интерактивного тренажёра   |
| **iReal Pro**             | Нет AI. Шаблоны сеток, ручной выбор стиля          | Высокий — все параметры вручную                             | Нет AI-генерации, нет естественно-языкового интерфейса     |
| **Band-in-a-Box**         | Генерация аккомпанемента по аккордам (rule-based)  | Средний — предустановленные стили, ручной ввод аккордов     | Десктоп, нет AI, нет веба, устаревший UX                   |
| **Amazilia (сейчас)** | Нет AI. Ручное создание сеток через DSL / редактор | Высокий — полный контроль                                   | **Нет AI-ассистента**                                      |
| **Amazilia (цель)**   | AI создаёт план, компилятор строит аранжировку     | Высокий — AI предлагает, пользователь контролирует и правит | **Единственный AI-ассистент для джазовых аранжировок**     |

**Рыночная ниша:** Ни один конкурент не предлагает AI-управляемое создание джазовой аранжировки с разделением на инструментальные дорожки, детерминированной компиляцией, preview в реальном времени и возможностью дальнейшего ручного редактирования. Suno/Udio генерируют «чёрный ящик» — готовый аудиофайл без доступа к отдельным партиям. Amazilia даёт AI-замысел + ручной контроль.

## 3. Новые функции (Features)

### 3.1. AI Orchestrator — ядро ассистента

- **Проблема:** Создание аранжировки требует знания DSL, стилей, инструментов, паттернов и уровней сложности. Новичок не может быстро получить звучащий результат. Опытный пользователь тратит время на рутинную настройку.
- **Описание:** Центральный модуль, принимающий промпт пользователя и управляющий цепочкой: исследование → Composition Plan → компиляция → валидация → preview. AI Orchestrator **не генерирует финальный объект композиции** — только абстрактный план. Работает по схеме:

```
Промпт → AI Orchestrator → [Знания сервиса + Интернет] → Composition Plan
       → Composition Compiler → Валидаторы → Preview / Сохранение
```

- **Конкуренты:** Suno/Udio — текстовый промпт → аудио (чёрный ящик). AIVA — текстовый промпт → MIDI (нет раздельных инструментов). **Никто не даёт промпт → раздельные дорожки → редактирование.**
- **Приоритет:** P0 (MVP)
- **Новая категория / Плагин:** `ai-assistant` (новый плагин, категория `admin` / `core`)
- **Зависимости:** 3.2 (Composition Plan DSL), 3.3 (Composition Compiler), 3.6 (DeepSeek-интеграция), StyleProfile (ADR-016), каталог инструментов

### 3.2. Composition Plan DSL — промежуточный слой

- **Проблема:** AI не должен напрямую генерировать внутренний объект композиции (с ID паттернов, MIDI-событиями, настройками Tone.js). Это приводит к галлюцинациям, несуществующим ID и невоспроизводимым результатам.
- **Описание:** Доменный DSL — абстрактный план композиции, независимый от реализации. Содержит: намерение (стиль, настроение, темп), гармонию (тональность, стратегия прогрессии, кривая напряжения), форму (секции с длительностью и энергией), ансамбль (роли инструментов, предпочтения, плотность). Пример:

```json
{
  "schemaVersion": "1.0",
  "intent": {
    "title": "Midnight Conversation",
    "style": "neo-soul",
    "mood": ["warm", "late-night", "restrained"],
    "tempo": 82,
    "timeSignature": "4/4",
    "complexity": 2,
    "durationTargetBars": 48
  },
  "harmony": {
    "key": "F minor",
    "harmonicLanguage": "extended-diatonic",
    "progressionStrategy": "smooth-voice-leading",
    "tensionCurve": "low-medium-high-low"
  },
  "form": [
    { "label": "Intro", "type": "intro", "bars": 4, "energy": 0.2 },
    { "label": "A", "type": "verse", "bars": 8, "energy": 0.4 },
    { "label": "B", "type": "solo", "bars": 16, "energy": 0.75 },
    { "label": "A2", "type": "verse", "bars": 8, "energy": 0.5 },
    { "label": "Outro", "type": "outro", "bars": 4, "energy": 0.2 }
  ],
  "ensemble": [
    {
      "role": "harmony",
      "instrumentPreference": "rhodes",
      "behavior": "syncopated-comping",
      "density": "medium"
    },
    {
      "role": "bass",
      "instrumentPreference": "electric-bass",
      "behavior": "melodic-groove",
      "density": "low"
    },
    {
      "role": "drums",
      "instrumentPreference": "drum-kit",
      "behavior": "laid-back-pocket",
      "density": "low"
    }
  ]
}
```

**План не содержит:** ID паттернов, MIDI-событий, названий несуществующих паттернов, внутренних настроек Tone.js.

- **Конкуренты:** Никто не использует промежуточный DSL между AI и движком. AIVA/Band-in-a-Box генерируют финальный объект напрямую.
- **Приоритет:** P0 (MVP)
- **Новая категория / Модуль:** `music-core` / `shared` (типы `CompositionPlan`, `CompositionPlanSchema`)
- **Зависимости:** Zod-валидация (3.8), каталог сервиса (3.4)

### 3.3. Composition Compiler — детерминированный компилятор

- **Проблема:** Нужен мост между абстрактным Composition Plan и реальным объектом композиции приложения. Этот мост должен быть детерминированным, тестируемым и написанным на TypeScript, а не ещё одном LLM-промпте.
- **Описание:** `compileComposition(plan, capabilities, rules) → CompileResult` — чистая функция в `music-core`:
  - **Style resolution:** маппинг пользовательского жанра на `StyleId` сервиса (5 стилей: swing, bossa, funk, latin, ballad). Неизвестные подстили резолвятся в ближайший доступный с явным указанием замены.
  - **Ensemble resolution:** `instrumentPreference` → реальный `InstrumentId` (из 12 доступных). Проверка доступности через `StyleProfile`.
  - **Form → sections:** создание секций с длительностью, привязка к `SectionType`.
  - **Pattern selection:** выбор паттернов для каждого инструмента по criteria (стиль, сложность, поведение, плотность) из каталога.
  - **Harmony generation:** создание аккордовой прогрессии по стратегии, тональности и кривой напряжения.
  - **Complexity profile:** разворачивание глобального `complexity` (1–4) в per-instrument профиль:

```json
{
  "complexity": 2,
  "overrides": {
    "bass": { "relativeComplexity": 1 }
  }
}
```

→

```json
{
  "piano": { "voicingComplexity": 2, "rhythmicDensity": 2, "variation": 1 },
  "bass": { "noteDensity": 3, "approachNotes": 1, "fills": 1 },
  "drums": { "limbDensity": 2, "ghostNotes": 0, "fills": 1 }
}
```

- **Конкуренты:** Band-in-a-Box — rule-based компилятор без AI-замысла. iReal Pro — фиксированные шаблоны. **Amazilia — единственный с AI-замыслом + детерминированной компиляцией.**
- **Приоритет:** P0 (MVP)
- **Модуль:** `music-core/src/ai/compiler.ts`
- **Зависимости:** 3.2 (Composition Plan DSL), 3.4 (каталог), StyleProfile (ADR-016), chordTimeline, TransportEngine

### 3.4. Каталог сервиса (Music Capabilities) — структурированный источник истины

- **Проблема:** AI должен знать, какие стили, инструменты, секции и паттерны реально существуют. Нельзя полагаться только на системный промпт — он устаревает и занимает контекст.
- **Описание:** Структурированный каталог `MusicCapabilities`, доступный AI через инструменты (tool calls):

```ts
interface MusicCapabilities {
  schemaVersion: string;
  styles: StyleDefinition[];
  instruments: InstrumentDefinition[];
  sectionTypes: SectionTypeDefinition[];
  timeSignatures: TimeSignature[];
  complexityLevels: ComplexityLevel[]; // 4 уровня
  patternCatalog: PatternDescriptor[];
  compatibilityRules: CompatibilityRule[];
}
```

**Инструменты для AI:**

- `get_service_capabilities()` — полный каталог (только метаданные, без деталей паттернов)
- `get_style_definition(styleId)` — детали стиля: темповый диапазон, инструменты, правила
- `get_instrument_capabilities(instrumentId)` — роли, паттерны, диапазон, voicing'и
- `search_available_patterns(criteria)` — релевантная выборка паттернов (не весь каталог)
- `get_arrangement_rules(criteria)` — правила аранжировки по фильтрам

- **Приоритет:** P0 (MVP)
- **Модуль:** `music-core/src/ai/capabilities.ts` + API-эндпоинты
- **Зависимости:** StyleProfile (ADR-016), манифесты инструментов (ADR-017), каталог паттернов

### 3.5. База правил аранжировки (RAG)

- **Проблема:** Музыкальные правила аранжировки (как строить walking bass, какие voicing'и для bossa nova, ограничения Intro/Outro) слишком объёмны для системного промпта. Нужен семантический поиск.
- **Описание:** Документированные правила аранжировки, разделённые по смыслу:

```
/rules/styles/jazz-swing.md
/rules/styles/bossa-nova.md
/rules/styles/funk.md
/rules/instruments/bass.md
/rules/instruments/piano.md
/rules/instruments/drums.md
/rules/forms/aaba.md
/rules/complexity/level-1.md — level-4.md
/rules/harmony/chord-density.md
```

Каждое правило с метаданными:

```json
{
  "ruleId": "bass.walking.chord-change",
  "version": "2.1",
  "style": ["jazz-swing"],
  "instrument": ["upright-bass"],
  "complexity": [2, 3, 4],
  "priority": "required"
}
```

**Поиск:** гибридный — фильтрация по метаданным + полнотекстовый BM25 + embeddings для смыслового поиска.

- **Приоритет:** P1 (полная версия). В MVP — ключевые правила в системном промпте.
- **Модуль:** `music-core/src/ai/rag/` + векторное хранилище
- **Зависимости:** 3.4 (каталог), embeddings API

### 3.6. DeepSeek V4 Flash — интеграция

- **Проблема:** Нужна быстрая, недорогая модель с поддержкой tool calling, JSON Output и большим контекстом.
- **Описание:** DeepSeek V4 Flash (`deepseek-v4-flash`) — основная модель. 1M контекст, tool calls, JSON Output, thinking/non-thinking режимы.

**Режимы работы:**

| Операция                    | Режим        | Temperature |
| --------------------------- | ------------ | ----------- |
| Определение намерения       | Non-thinking | 0–0.1       |
| Решение, нужен ли интернет  | Non-thinking | 0           |
| Исследование жанра          | Thinking     | 0.2         |
| Создание Composition Plan   | Thinking     | 0.15–0.25   |
| Исправление ошибок (repair) | Non-thinking | 0           |
| Объяснение пользователю     | Non-thinking | 0.4         |

**Творческое разнообразие** — через явный параметр `variationSeed` + `novelty`, а не через высокую температуру. Одинаковый seed + промпт = воспроизводимый результат.

**Контекстное кеширование:** Стабильная часть (правила, DSL, инструменты, примеры) в начале контекста → DeepSeek автоматически кеширует совпадающие префиксы.

- **Приоритет:** P0 (MVP)
- **Модуль:** `music-core/src/ai/orchestrator.ts` + API-прокси
- **Зависимости:** DeepSeek API key, 3.2 (DSL), 3.4 (каталог)

### 3.7. Система валидации (4 уровня)

- **Проблема:** Strict JSON Schema гарантирует форму, но не музыкальную корректность. Нужна многоуровневая проверка.
- **Описание:** Четыре уровня валидации:

**Уровень 1 — Schema (Zod):**

```ts
const result = CompositionPlanSchema.safeParse(plan);
```

Проверка: обязательные поля, типы, enum, диапазоны, отсутствие лишних полей, версия схемы.

**Уровень 2 — Referential:**
Проверка существования: стиль → есть в StyleProfile, инструмент → есть в каталоге, паттерн → существует, размер → поддерживается, ID не устаревшие.

**Уровень 3 — Музыкальная:**

- Суммарная длительность аккордов = длительность такта
- Паттерн поддерживает размер
- Бас учитывает смены аккорда
- Voicing в диапазоне инструмента
- Intro/Outro без максимальной плотности
- Секции музыкально разумной длины
- Переходы между секциями существуют

**Уровень 4 — Runtime (перед сохранением):**

- Компиляция событий без ошибок
- Нет отрицательных duration
- Полифония в пределах лимита
- Все сэмплы доступны
- Тестовый offline render нескольких тактов

- **Приоритет:** P0 (MVP, уровни 1–2 обязательно; 3–4 — в полной версии)
- **Модуль:** `music-core/src/ai/validator.ts`
- **Зависимости:** 3.2 (DSL), 3.3 (Compiler), 3.4 (каталог)

### 3.8. Цикл автоматического исправления (AI Repair)

- **Проблема:** При ошибке валидации не нужно просить модель перегенерировать всю композицию заново.
- **Описание:** Валидатор возвращает структурированные ошибки:

```json
{
  "valid": false,
  "errors": [
    {
      "code": "UNSUPPORTED_TIME_SIGNATURE",
      "path": "/sections/2/timeSignature",
      "value": "7/8",
      "allowed": ["4/4", "3/4", "2/4", "5/4", "6/8"]
    }
  ]
}
```

Модель возвращает только patch:

```json
{
  "operations": [{ "op": "replace", "path": "/sections/2/timeSignature", "value": "4/4" }],
  "explanation": "7/8 не поддерживается стилем, заменён на 4/4."
}
```

**Ограничение:** максимум 3 попытки. После — объяснение пользователю конфликта.

- **Приоритет:** P1 (полная версия). В MVP — одна попытка.
- **Модуль:** `music-core/src/ai/repair.ts`
- **Зависимости:** 3.7 (валидация)

### 3.9. Интернет-поиск (с защитой)

- **Проблема:** Пользователь может запросить неизвестный подстиль, особенности исполнителя или историческую точность. Нужен веб-поиск, но интернет — недоверенный источник.
- **Описание:** Веб-поиск включается только когда:
  - Неизвестный или редкий подстиль
  - Запрос особенностей исполнителя/жанра
  - Ссылка на конкретную композицию
  - Запрос исторически точной аранжировки
  - Понятие отсутствует в базе знаний

Результаты преобразуются в нейтральный объект признаков:

```json
{
  "styleTraits": [
    { "trait": "laid-back backbeat", "confidence": 0.86, "sources": ["..."] },
    { "trait": "extended seventh and ninth chords", "confidence": 0.91, "sources": ["..."] }
  ]
}
```

**Защита:**

- Белый/чёрный список источников
- Ограничение объёма текста
- Удаление HTML и скриптов
- Запрет инструкций с веб-страниц
- Разделение фактов, предположений и интерпретаций
- Запрет копирования полной мелодии
- Сохранение URL и даты обращения

Запрос «Сделай как So What Майлза Дэвиса» преобразуется в общие признаки (modal-jazz, spacious, slow harmonic rhythm) — **не** в копию аранжировки.

- **Приоритет:** P2 (полная версия). В MVP — без интернет-поиска.
- **Модуль:** API-прокси для веб-поиска
- **Зависимости:** 3.6 (DeepSeek), search API (Brave/SerpAPI)

### 3.10. UX ассистента — чат и diff

- **Проблема:** Пользователь должен видеть, что именно меняет AI, и иметь возможность отклонить или скорректировать изменения.
- **Описание:** Чат-интерфейс рядом с аранжировкой. Четыре сценария:
  1. **Создать:** «Сделай блюз на 12 тактов в F, несложный, с органом и гитарой»
  2. **Изменить:** «Вторая секция скучная — добавь напряжения, но не усложняй барабаны»
  3. **Объяснить:** «Почему здесь бас играет именно так?»
  4. **Предложить:** «Какие три варианта развития после этой секции?»

**Diff перед применением:**

```
Предлагаемые изменения

Форма: AABA → AABA + Solo
Длительность: 32 → 48 тактов
Rhodes: complexity 2 → 3 только в Solo
Bass: half notes → walking quarters в Solo
Drums: добавлен fill в конце каждого 8-тактового периода

[Применить] [Прослушать] [Сделать проще] [Больше разнообразия] [Другой вариант] [Отмена]
```

**Инкрементальные правки:**

- `propose_composition_patch(patch)` — показать изменения
- `apply_composition_patch(patch, confirmationToken)` — применить только после подтверждения

- **Приоритет:** P0 (MVP — базовый чат и diff). P1 (полная версия — все 4 сценария).
- **Плагин:** `ai-assistant` (новый, категория `admin` / `core`)
- **Зависимости:** 3.1 (Orchestrator), 3.3 (Compiler)

## 4. Улучшения существующих функций

### 4.1. Расширение StyleProfile для AI

- Добавить в `StyleProfile` метаданные для AI: текстовое описание стиля, типичные инструменты, темповый диапазон, музыкальные характеристики
- `StyleDefinition` должен включать `aiDescription`, `typicalInstruments`, `tempoRange`, `musicalTraits`

### 4.2. Расширение InstrumentManifest для AI

- Добавить `aiDescription`, `roles`, `behaviors`, `densityLevels` в `InstrumentManifest`
- Эти поля — источник для `MusicCapabilities`, не дублирование

### 4.3. API-эндпоинты для AI Orchestrator

- `POST /api/ai/compose` — создать композицию из промпта
- `POST /api/ai/modify` — изменить существующую
- `POST /api/ai/validate` — провалидировать план
- `GET /api/ai/capabilities` — каталог сервиса
- `POST /api/ai/preview` — сгенерировать preview

### 4.4. История версий композиций

- Сохранение Composition Plan + скомпилированной композиции как версии
- Возможность отката к предыдущей версии
- Кнопка «Вернуть предыдущую версию» в UX

## 5. Не войдёт в эту версию (Out of Scope)

### MVP — не войдёт:

- Пользовательский доступ (только админка)
- Интернет-поиск (только каталог сервиса + правила)
- RAG-поиск по базе правил (ключевые правила — в системном промпте)
- Сценарии «объяснить» и «предложить» (только «создать» и «изменить»)
- Уровни валидации 3–4 (только Schema + Referential)
- Цикл автоматического исправления (только одна попытка, затем ошибка пользователю)
- Пользовательские подстили за пределами 5 стилей (swing, bossa, funk, latin, ballad)
- Секции нестандартной длины
- Генерация гармонии «с нуля» (только на основе существующих прогрессий)

### Полная версия — не войдёт:

- Генерация аудио (AI не генерирует звук — только аранжировку)
- Автономный AI-агент без участия пользователя
- Мультимодальный ввод (голос, видео)
- Интеграция с внешними AI-сервисами кроме DeepSeek
- Десктопная версия ассистента

## 6. Риски и допущения

| Риск                                                                      | Решение                                                                                                                                                                 |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DeepSeek V4 Flash галлюцинирует ID паттернов                              | AI не генерирует ID. Composition Compiler (TypeScript) резолвит всё детерминированно. AI оперирует только ролями, поведениями и плотностями.                            |
| Модель «придумывает» несуществующие стили                                 | Каталог сервиса — единственный источник истины. Неизвестный стиль резолвится в ближайший доступный с явным указанием замены.                                            |
| Контекст 1M токенов не бесконечен при частых обращениях                   | Контекстное кеширование DeepSeek (стабильный префикс). Каталог паттернов не передаётся целиком — только релевантная выборка через `search_available_patterns()`.        |
| План не компилируется (несовместимые комбинации стиль/инструмент/паттерн) | Рефереренциальная валидация перед компиляцией. Несовместимость → замена с объяснением или вопрос пользователю.                                                          |
| Качество аранжировки ниже ручной                                          | Критерий MVP: «воспроизводится без ошибок и музыкально осмысленно», не «звучит как профессиональная студийная запись». Качество растёт с расширением каталога и правил. |
| DeepSeek API недоступен или медленный                                     | Таймаут + fallback-сообщение пользователю. Ассистент — удобство, не критический путь (пользователь всегда может создать композицию вручную).                            |
| Интернет-поиск возвращает вредоносные инструкции                          | Защита: белый список источников, очистка HTML, преобразование в признаки, запрет инструкций. Системный промпт явно запрещает следовать указаниям с веб-страниц.         |
| Увеличение числа настроек пугает пользователя                             | Базовый complexity (1–4) — единственный обязательный параметр. Всё остальное — опциональные уточнения. UX: один слайдер сложности + чат для деталей.                    |
| Ассистент в админке требует прав, которых нет у обычного пользователя     | MVP — админка только (права уже есть). Полная версия — новое permission `ai:use` для пользователей.                                                                     |

## 7. Метрики успеха

### MVP:

- Администратор описывает композицию словами → валидный Composition Plan за <5 секунд
- Plan компилируется в воспроизводимую композицию без ошибок (все паттерны/инструменты — реальные ID)
- Preview проигрывается без артефактов
- Изменение композиции через чат (поменять стиль, добавить секцию) — корректный diff
- История версий: откат к предыдущей возвращает точное состояние
- `typecheck` + `lint` + `test` — зелёные
- Одинаковый seed + промпт → одинаковый результат (воспроизводимость)

### Полная версия:

- Пользователь создаёт композицию за <3 сообщения в чате
- 90% запросов «создай X» проходят валидацию с первой попытки
- 80% запросов «измени Y» применяются без ручных правок
- N композиций создано через AI / неделю
- Время от промпта до preview <10 секунд

### Критерий качества (тестовый набор):

Набор из 100–300 эталонных запросов:

- «Создай простой swing в Bb на 32 такта»
- «Сделай bossa nova без перкуссии»
- «Добавь соло после второго припева»
- «Пусть бас будет активнее, но общий уровень останется 2»
- «Сделай музыку в духе джазового клуба 1950-х»

Автотест проверяет: JSON валиден, только реальные ID, композиция воспроизводится, аккорды в тактах, сложность в профиле, одинаковый seed = одинаковый результат, изменение секции не ломает остальные, неподдерживаемая фича корректно заменена или отклонена.
