# ADMIN-DEFAULT-INSTRUMENT-SETTINGS — План реализации (без T-011)

> Бриф: `docs/ADMIN-DEFAULT-INSTRUMENT-SETTINGS.md`.
> **Уточнения с пользователем:**
> **(A)** Per-style значения берутся из `StyleProfile` через `applyStyleDefaults` (как у `user_settings`); `default_settings.perStyleOverrides` стартует пустым и хранит только то, что админ явно переопределил. Дублирования StyleProfile нет.
> **(B)** T-011 (`rhodesRegister`) **выкинут полностью** — Rhodes остаётся обычным инструментом, как piano/bass/и т.д. Звуковой движок не трогаем.

## Ключевая архитектура

`default_settings` — singleton-таблица (id=1), зеркало `user_settings` **без** персональных полей (`userId`, `practiceCards`, `midiDeviceId`, `midiChannel`) и **без** `rhodesRegister`. Как и `user_settings`, не хранит per-style значения явно — они резолвятся через `applyStyleDefaults(settings, style)` на лету. Поведение: «заводские настройки» — админ задаёт глобальные дефолты, новые пользователи наследуют, существующих не трогают.

## ЭТАП 1 — Слой данных + миграции (T-001, T-002)

### 1.1 `apps/api/src/db/schema.ts`

- Добавить таблицу `defaultSettings` (singleton, `id integer PK default 1`). Колонки = все скалярные поля `userSettings` **кроме** `userId`, `practiceCards`, `midiDeviceId`, `midiChannel`. Включает `perStyleOverrides text`, `createdAt/updatedAt integer`. **Без `rhodesRegister`.**
- Существующую таблицу `userSettings` не трогаем.

### 1.2 Миграции (drizzle-kit generate)

- Запустить `npm run db:generate -w @jazz/api` для авто-генерации `0036_default_settings.sql` и обновления `drizzle/meta/_journal.json` + snapshot. Ручная правка SQL не требуется.
- `runMigrations` в `src/db/migrate.ts` уже вызывается при старте (`src/index.ts:29`) — на prod-БД применится автоматически.

### 1.3 `apps/api/src/db/seed.ts` — `seedDefaultSettings()`

- Новая функция: вставляет singleton-строку idempotently (`INSERT ... ON CONFLICT(id) DO NOTHING`).
- Значения = текущие хардкод-дефолты (bpm=120, volume=0.8, countIn=1, metronome-блок, bass/rhodes/piano/drums базовые скаляры как в схеме `userSettings`, swingRatio=0.5, audioFormat='aac', soloToneId='rhodes-jrhodes3c', click sounds='drum-stick', `perStyleOverrides=null`).
- **Per-style значения НЕ сидируются** — `applyStyleDefaults` возьмёт их из `StyleProfile` (решение A).
- Подключить в оркестрацию seed рядом с `seedRbac`.

## ЭТАП 3 — API (T-004, T-005)

### 3.1 `apps/api/src/services/defaults.service.ts` (NEW)

- `getDefaultSettings(db): DefaultSettingsDTO` — селект singleton; если нет → хардкод-дефолты (fallback §4.2); применяет `applyStyleDefaults(dto, dto.style)` через `toDefaultSettingsDTO` (зеркало `toSettingsDTO` из auth.service).
- `upsertDefaultSettings(db, patch)` — merge в существующую строку или insert (per-style скаляры складываем в `perStyleOverrides[currentStyle]`, как в `settings.routes.ts`).
- `resetDefaultSettings(db)` — перезаписать на хардкод-дефолты.

### 3.2 `apps/api/src/routes/defaults.routes.ts` (NEW)

- `GET /api/admin/default-settings` → `requireAuth` + `requirePermission('system:settings:read')` (админский, без кеша).
- `PUT /api/admin/default-settings` → `requirePermission('system:settings:write')` + `withAuditSync(..., 'default_settings.update', ...)`.
- `PATCH /api/admin/default-settings` → то же + rate-limit 1 req / 5s (простой in-memory timestamp-guard; стандартного rate-limit плагина в проекте нет).
- `POST /api/admin/default-settings/reset` → `requirePermission('system:settings:write')` + audit `'default_settings.reset'`.
- `GET /api/default-settings` → **публичный** (без auth), заголовок `Cache-Control: public, max-age=60`. Возвращает резолвленные дефолты.
- Зарегистрировать в `apps/api/src/server.ts`: `await app.register(defaultsRoutes, { prefix: '/api', db });` рядом с остальными admin-роутами.

### 3.3 Инициализация новых пользователей (T-005)

- `apps/api/src/services/auth.service.ts` → `ensureUserSettings(db, userId)`:
  - Если строка уже есть → return.
  - Читать singleton из `defaultSettings`; если есть → `INSERT INTO user_settings` со значениями из `defaultSettings` + `{ userId, createdAt, updatedAt }` (без персональных полей).
  - Если singleton отсутствует (fallback) → текущие хардкод-дефолты.
- `toSettingsDTO` — без изменений (rhodesRegister не вводили).

## ЭТАП 4 — SDK (T-006, T-007)

### 4.1 `packages/plugin-sdk/src/queries/useDefaultSettings.ts` (NEW)

- `const DEFAULT_SETTINGS_KEY = ['default-settings'] as const;`
- `useDefaultSettings()` → `useQuery({ queryKey, queryFn: () => apiClient.get<DefaultSettingsDTO>('/api/default-settings'), staleTime: 60_000 })`. Без auth-gating (публичный, для гостей).

### 4.2 `packages/plugin-sdk/src/queries/useEffectiveSettings.ts`

- Гостевой путь: `applyStyleDefaults(merge(defaultSettings, localSettings), style)` вместо `applyStyleDefaults(localSettings, style)`.
- `defaultSettings` из `useDefaultSettings()`; `localSettings` приоритетнее (гость мог локально подстроить).
- Если `defaultSettings` ещё грузится → fallback на текущее поведение (только localSettings).

### 4.3 `packages/plugin-sdk/src/index.ts`

- Экспортировать `useDefaultSettings`.

## Валидация

После каждого этапа:

1. `npm run typecheck` — типы/импорты.
2. `npm run lint` — границы слоёв (`boundaries/dependencies`). Плагин admin-defaults может импортировать только `@jazz/plugin-sdk`, `@jazz/shared`.
3. `npm run test` — после изменений логики. Существующие тесты `styleSettings`, `rbac.service` должны пройти; новые — contract-тест плагина.
4. Проверить, что `db:generate` создал миграцию без конфликтов, а `runMigrations` применяет её чисто (dev-БД пересоздастся).
